Fundamentals

What a .tmx map file actually contains

A .tmx file is made in a free editor called Tiled. It is not one picture — it's a stack of named layers, and each layer is one of two kinds.

🧱 Tile layers

A grid of tiles. Reading one gives you (col, row, image) for every square — used once, for Terrain.

📦 Object layers

A list of placed rectangles, each with its own x, y, width, height, and custom properties set by the map artist.

This map has 8 layers: Terrain, Terrain Top, Water, Coast, Objects, Transition, Collisions, Monsters, Entities. tmx_map.get_layer_by_name('Water') gets you exactly one of them.

Fundamentals

Draw order and the camera

Every sprite carries a z number. The game draws low z first, so higher numbers sit on top:

top z=4
main z=3
bg z=1
water z=0

offset.x = -(player.centerx - WINDOW_WIDTH/2) — every sprite is drawn shifted by this amount, which keeps the player fixed at screen-centre while the world slides underneath.

On the main layer only, sprites are sorted by y_sort before drawing — the one lower on screen draws last, so it appears in front.

Fundamentals

Why every sprite carries two boxes, not one

A sprite's rect and its hitbox are not the same rectangle on purpose. They do two different jobs, and using one box for both jobs breaks one of them.

🖼️ rect draws the picture

rect always matches the actual image size — for the player, 128×128. It has to: this is the box blit() uses to place the artwork on screen. Shrink it, and the artwork gets cropped or offset.

🤝 hitbox decides what's touching what

Character art usually has empty space baked into the frame — room above the head, room around the feet, so the walk animation doesn't jitter. hitbox is a smaller box placed inside that empty space, matching the actual body.

rect — the full 128×128 frame
hitbox — just the body

Only one box existed? Use rect for collisions and we'd stop walking — or trigger a door — while still a visible gap away from it, because empty space around the sprite counts as "touching." Use hitbox for drawing and the artwork gets squashed into a box too small for it. Two boxes, two jobs: every collision in this game — walls, rocks, NPCs, doors — always compares hitbox, never rect.

Fundamentals — Step 14

AnimatedSprite: cycling through a list of images

Water and coast tiles are each a short list of frames — separate images, not one moving picture. frame_index is a counter that climbs every frame; converting it to an integer and picking frames[index] is what makes the image change.

Worked example: say there are 4 water frames and ANIMATION_SPEED = 6. After 1 second, frame_index has climbed to 6. 6 % 4 = 2, so the sprite shows frames[2]. Once frame_index passes 4, % wraps it back toward 0 — the loop never runs out of frames.

AnimatedSprite inherits from pygame.sprite.Sprite directly — it needs its own image, rect, hitbox, z, and y_sort, same fields as last session's Sprite class, just built from a list of frames instead of one surface.

class AnimatedSprite(pygame.sprite.Sprite):
    def __init__(self, pos, frames, groups, z=WORLD_LAYERS['main']):
        self.frame_index = 0
        self.frames = frames
        super().__init__(groups)
        self.image  = self.frames[0]
        self.rect   = self.image.get_frect(topleft=pos)
        self.z      = z
        self.hitbox = self.rect.copy()
        self.y_sort = self.rect.centery

    def animate(self, dt):
        self.frame_index += ANIMATION_SPEED * dt
        self.image = self.frames[int(self.frame_index % len(self.frames))]

    def update(self, dt):
        self.animate(dt)
Fundamentals — Step 15

MonsterPatchSprite: marking an encounter zone

A monster patch is a tile placed by the map artist with three custom properties: biome, monsters, and level. It inherits from AnimatedSprite — same frame-cycling, plus three extra pieces of data.

🌾 Sand draws behind, grass draws level

Sand patches use z = bg so the player appears to walk over the sand. Every other biome uses z = main like a normal obstacle.

📝 monsters is one string, not a list

Tiled stores 'Atrox,Pouch' as plain text. .split(',') turns it into ['Atrox', 'Pouch'] — one of several monsters that patch can produce.

Fundamentals — Step 18

transition_check(): applying the two-box rule to doors

pygame.sprite.spritecollide() compares .rect by default — but we just established that collisions should always compare hitbox. Doors are a collision like any other, so this function needs to be told explicitly to check the smaller box.

Passing collided=lambda a, b: a.hitbox.colliderect(b.hitbox) overrides the default comparison. Without it, the door would react to the player's full 128×128 frame — triggering while still visibly outside the doorway.

def transition_check(self):
    sprites = pygame.sprite.spritecollide(
        self.player, self.transition_sprites, False,
        collided=lambda a, b: a.hitbox.colliderect(b.hitbox))
    if sprites:
        self.player.block()
        self.transition_target = sprites[0].target
        self.tint_mode = 'tint'
Fundamentals — tint_screen()

What makes the screen actually fade to black

transition_check() only sets self.tint_mode = 'tint'. The fade itself, and the moment the map actually swaps, happen in tint_screen(dt) — already written, running every single frame no matter what.

tint_surf is a plain black rectangle covering the whole window. tint_progress is one number from 0 to 255 that doubles as that rectangle's transparency: tint_surf.set_alpha(tint_progress). At 0 it's invisible; at 255 it's solid black.

mode='tint'
progress 0→255
→
screen fully black
→
setup() swaps
the map
→
mode='untint'
progress 255→0
→
new map
revealed

The map swap is written to happen only the instant tint_progress reaches 255 — the exact moment the screen is completely black. That's why we never see the old map disappear or the new one pop in: it's already switched behind a black screen before the fade back in even starts.
