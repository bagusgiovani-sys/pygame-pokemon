Core concept

What is a game loop?

Every game runs a loop that repeats 60+ times per second. Each pass through the loop is one frame.

① Events
keyboard / quit
→
② Update
move things
→
③ Draw
fill, blit, update
↺

In code this is just a while True: loop. Pygame keeps it running until you close the window.

Core concept

Delta time — why does it matter?

🐌
30 fps

Slow PC
moves 5px per frame
= 150 px/s

🚀
120 fps

Fast PC
moves 5px per frame
= 600 px/s

Fix: move by pixels-per-second × dt instead of pixels-per-frame.
dt = self.clock.tick() / 1000 — gives seconds since last frame (e.g. 0.016).
Both PCs now move 300 × 0.033 ≈ 300 × 0.008 = same speed ✓

main.py — __init__
Starting pygame

Inside __init__, write these four lines:

def __init__(self):
    pygame.init()
    self.display_surface = pygame.display.set_mode((WINDOW_WIDTH, WINDOW_HEIGHT))
    pygame.display.set_caption('Monster Game')
    self.clock = pygame.time.Clock()
  • pygame.init() — boots every pygame sub-system (display, font, sound…). Always first.
  • set_mode(...) — asks the OS to open a window. Returns a Surface — the whole screen.
  • set_caption(...) — sets the text in the title bar.
  • Clock() — a timer we'll use to measure delta time each frame.
Concept

What is a Surface?

In pygame, a Surface is just a rectangle of pixels — like a digital canvas. You can draw on it, copy images onto it, and display it on screen.

display_surface

The screen itself. Everything you draw goes here. Created by set_mode(). 1280 × 720 pixels.

player_surf

A small 48 × 64 Surface filled with green — a placeholder for our player sprite. In session 2 this becomes a real animated character.

blit = copy one surface onto another at a position.
display_surface.blit(player_surf, player_rect) stamps the player onto the screen.

3
main.py — run()
The game loop 
def run(self):
    while True:
        dt = self.clock.tick() / 1000       # ① delta time in seconds

        for event in pygame.event.get():  # ② handle events
            if event.type == pygame.QUIT:
                pygame.quit()
                exit()

        self.display_surface.fill('black')              # ③ clear screen
        self.display_surface.blit(self.player_surf, self.player_rect)  # ④ draw
        pygame.display.update()                 # ⑤ show frame
Explained line by line

What each line does

  • ① clock.tick() / 1000 — how many seconds since last frame. ~0.016 at 60fps.
  • ② event.get() — drains pygame's event queue. The OS sends a QUIT event when you click ✕.
  • ③ fill('black') — paints the whole screen black. Without this, the last frame's pixels linger behind the player.
  • ④ blit(surf, rect) — stamps the player surface onto the screen at the player's position.
  • ⑤ display.update() — pygame draws to a hidden back-buffer; update() flips it to the screen to prevent flickering.
Common mistake

Why do we fill before we blit?

❌ Without fill

Every frame draws on top of the last frame. If the player moves, you see a trail of old positions left behind — like painting without a canvas reset.

✅ With fill first

The screen is wiped clean each frame before drawing. The player appears in exactly one place — clean and crisp.

Rule: always draw in this order every frame:
fill() → draw background → draw entities → display.update()
