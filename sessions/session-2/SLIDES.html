Diagonal problem: pressing UP + RIGHT gives (1, 1) — length ≈ 1.41, so the player moves 41% faster diagonally.
Fix: input_vector.normalize() — rescales any vector to length exactly 1.

4
update() — check every frame 
def update(self):
    if self.active:
        current_time = get_ticks()
        if current_time - self.start_time >= self.duration:
            if self.func:
                self.func()
            self.deactivate()

Call timer.update() every frame — otherwise it never checks whether it's expired.

entities.py — Entity
animate(dt) — cycle through frames

Two lines: advance the counter, then pick the correct frame image.

def animate(self, dt):
    self.frame_index += ANIMATION_SPEED * dt
    state = self.get_state()          # e.g. 'down', 'right_idle'
    self.image = self.frames[state][int(self.frame_index % len(self.frames[state]))]
  • ANIMATION_SPEED * dt — moves the counter by ~0.1 each frame (6 frames/s at 60fps).
  • get_state() — returns the dict key: 'down', 'left_idle', 'up', etc.
  • % len(...) — modulo wraps the index back to 0 when it reaches the end of the list.

Example: frame_index = 7.4, list has 4 frames → int(7.4 % 4) = int(3.4) = 3 — last frame. Next: wraps to 0.

Player.__init__ — three lines

Player inherits from Entity. Your __init__ just calls super and stores two extra things.

def __init__(self, pos, frames, groups, facing_direction, collision_sprites):
    super().__init__(pos, frames, groups, facing_direction)
    self.collision_sprites = collision_sprites
    self.noticed = False
  • super().__init__(...) — runs Entity's setup: sets rect, hitbox, frames, direction, speed.
  • collision_sprites — the group of walls the player collides with.
  • noticed = False — becomes True when an NPC spots you (used in dialog flow).

inheritance: super().__init__() runs the parent class constructor. Everything Entity builds (rect, hitbox, speed…) is then available as self.rect, self.speed, etc.

Concept

Two ways to read the keyboard

get_pressed()

Returns a list: True every frame the key is held down.

Perfect for movement — player keeps walking while you hold the key.

keys = pygame.key.get_pressed()
if keys[pygame.K_RIGHT]: ...

get_just_pressed()

Returns True only on the single frame the key was first pressed.

Perfect for dialog advance, menu clicks — fires once per keypress no matter how long you hold.

keys = pygame.key.get_just_pressed()
if keys[pygame.K_SPACE]: ...

Rule of thumb: movement → get_pressed()  |  "press to confirm" → get_just_pressed()

entities.py — Player
input() — read the keyboard 
def input(self):
    keys = pygame.key.get_pressed()
    input_vector = vector()            # starts at (0, 0)
    if keys[pygame.K_UP]:    input_vector.y -= 1
    if keys[pygame.K_DOWN]:  input_vector.y += 1
    if keys[pygame.K_LEFT]:  input_vector.x -= 1
    if keys[pygame.K_RIGHT]: input_vector.x += 1
    self.direction = input_vector.normalize() if input_vector else input_vector

Why if input_vector else input_vector? Calling .normalize() on a zero-length vector (no key held) crashes with a ValueError — dividing by zero. The check skips normalize when no key is pressed.

entities.py — Player
move(dt) — move in two passes 
def move(self, dt):
    self.rect.centerx  += self.direction.x * self.speed * dt  # ① move x
    self.hitbox.centerx = self.rect.centerx                   # ② sync hitbox
    self.collisions('horizontal')                             # ③ push back x
    self.rect.centery  += self.direction.y * self.speed * dt  # ④ move y
    self.hitbox.centery = self.rect.centery                   # ⑤ sync hitbox
    self.collisions('vertical')                               # ⑥ push back y

Why not move x+y together? If the player hits a corner, pygame can't tell which wall to push back from. Resolving x first, then y, means each collision is unambiguous — the player slides smoothly along walls instead of getting stuck.

Concept

The hitbox — smaller than the sprite

The visible image is taller than the collision area. The hitbox only covers the character's feet — so they can walk close to trees without the leaves blocking them.

❌ full rect hitbox
collision at shoulders
✅ inflate(-w/2, -60)
collision only at feet

self.hitbox = self.rect.inflate(-self.rect.width / 2, -60)
inflate(-x, -y) shrinks the rect by x px on each side horizontally and y px on each side vertically.
Always keep hitbox and rect in sync after moving: self.hitbox.centerx = self.rect.centerx

entities.py — Player
collisions(axis) — push back 
def collisions(self, axis):
    for sprite in self.collision_sprites:
        if sprite.hitbox.colliderect(self.hitbox):
            if axis == 'horizontal':
                if self.direction.x > 0: self.hitbox.right = sprite.hitbox.left
                if self.direction.x < 0: self.hitbox.left  = sprite.hitbox.right
                self.rect.centerx = self.hitbox.centerx
            else:
                if self.direction.y > 0: self.hitbox.bottom = sprite.hitbox.top
                if self.direction.y < 0: self.hitbox.top    = sprite.hitbox.bottom
                self.rect.centery = self.hitbox.centery

Moving right → push hitbox's right edge to the sprite's left edge. Then sync rect back to hitbox. Always update both rect and hitbox after a push.

setup() — player + four walls 
def setup(self):
    self.player = Player(
        pos=(WINDOW_WIDTH / 2, WINDOW_HEIGHT / 2),
        frames=self.overworld_frames['characters']['player'],
        groups=self.all_sprites,
        facing_direction='down',
        collision_sprites=self.collision_sprites)
    # four invisible border walls
    BorderSprite((0, 0),                        pygame.Surface((WINDOW_WIDTH, 20)),   self.collision_sprites)  # top
    BorderSprite((0, WINDOW_HEIGHT - 20),       pygame.Surface((WINDOW_WIDTH, 20)),   self.collision_sprites)  # bottom
    BorderSprite((0, 0),                        pygame.Surface((20, WINDOW_HEIGHT)),   self.collision_sprites)  # left
    BorderSprite((WINDOW_WIDTH - 20, 0),       pygame.Surface((20, WINDOW_HEIGHT)),   self.collision_sprites)  # right

Note: BorderSprite only goes in self.collision_sprites — not all_sprites. Invisible walls don't need to be drawn.
